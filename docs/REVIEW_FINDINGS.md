# Adversarial review: findings and resolutions

Before submission, an independent reviewer that had not seen the build reasoning checked the repository against its own claims. This log records every finding and what was done about it.

| ID  | Severity | Finding                                                                                                                                                                                  | Resolution                                                                                                                                                                                                                                                                                                  |
| --- | -------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| H1  | High     | The sandbox authorized returns only when read back, and only AFTERCARE reads them back. Four baseline runs that created the right return were scored wrong, and the docs did not say so. | **Fixed.** The harness lets the retailer settle before judging records. "False confirmations" was renamed "Confirmed before verifying" and kept as a separate behaviour. The headline changed from 14 vs 3 to **14 vs 7**. The docs were corrected, including an inaccurate claim about scenario isolation. |
| H2  | High     | The bare word "stop" triggered cancellation, so "they just stop working" could close a case and decline an approved proposal.                                                            | **Fixed.** Only explicit phrases cancel, and never in a message that describes a fault. Tested at the interpreter and service level.                                                                                                                                                                        |
| H3  | High     | A verified return on different terms was stored as "rejected" and shown as refused, although a return existed.                                                                           | **Fixed.** Added a `mismatch` status (migration 003, tested for data preservation), lifecycle stage, customer message, Lab state, and a sandbox outcome (`accept_with_fee`) that produces it.                                                                                                               |
| H4  | High     | "The version in effect on the order date governs" was a code constant that the seed policies never stated, while the docs said labels came from the policy text.                         | **Fixed.** Each policy version now declares its scope (`appliesTo`) in the data, and the decision trace quotes it.                                                                                                                                                                                          |
| H5  | High     | Over MCP, approval is only as strong as the client; the docs implied more.                                                                                                               | **Documented.** Added to the threat model's known risks, with stronger options (elicitation, read-back code). The README wording was made precise.                                                                                                                                                          |
| M1  | Medium   | After a failed attempt and a change of terms, the lifecycle showed "not executed" instead of the new proposal, hiding the approve button.                                                | **Fixed.** A finished operation for an older proposal no longer decides the stage (part of the mismatch change in `views.ts`).                                                                                                                                                                              |
| M2  | Medium   | S12 counted as an "unsupported action" although the item was eligible.                                                                                                                   | **Fixed.** Ground truth now separates the eligible order from the expected outcome.                                                                                                                                                                                                                         |
| M3  | Medium   | S14 counted as an authorization violation; the real error was wrong terms.                                                                                                               | **Fixed.** New "wrong terms submitted" metric.                                                                                                                                                                                                                                                              |
| M4  | Medium   | The web surface wrote approval text and the schema called it the customer's verbatim words.                                                                                              | **Fixed.** The surface records the control used ("Pressed Approve and send return"), and the schema says the field is what the client captured.                                                                                                                                                             |
| M5  | Medium   | Opening a case by URL briefly showed the welcome screen and starters, and a failed load had no proper state.                                                                             | **Fixed.** Added loading and could-not-open states.                                                                                                                                                                                                                                                         |
| M6  | Medium   | The requirements doc referenced a README Deployment section that did not exist.                                                                                                          | **Fixed.** Added the section. This also exposed that `tsx` (needed by `npm start`) was a dev dependency; it is now a runtime dependency.                                                                                                                                                                    |
| M7  | Medium   | Untested paths: decline, chat cancel, mismatch, lookup timeout, approving a superseded proposal, concurrent submits; two assertions only checked that something threw.                   | **Fixed.** Tests added for each; weak assertions now check exact error codes and an unchanged retailer request log. Dead `closeCase` was removed.                                                                                                                                                           |
| L1  | Low      | A scenario-file comment misdescribed which scenarios use which order.                                                                                                                    | **Fixed.**                                                                                                                                                                                                                                                                                                  |
| L2  | Low      | The read-only `get_case` tool wrote audit events.                                                                                                                                        | **Fixed.** Read-only tools no longer write.                                                                                                                                                                                                                                                                 |
| L3  | Low      | The Lab's comparison lacked a synthetic-data caveat, and evaluation load errors were swallowed.                                                                                          | **Fixed.**                                                                                                                                                                                                                                                                                                  |
| L4  | Low      | The newest operation was chosen by millisecond timestamp, which can tie.                                                                                                                 | **Fixed.** Creation order is used.                                                                                                                                                                                                                                                                          |
| L5  | Low      | `Math.random` in demo carrier references.                                                                                                                                                | **Fixed.** Derived from the injected clock.                                                                                                                                                                                                                                                                 |
| L6  | Low      | "Signed in as" implied authentication that does not exist.                                                                                                                               | **Fixed.** Now "Acting as".                                                                                                                                                                                                                                                                                 |
| L7  | Low      | The "not an Amazon product" notice was only a tooltip.                                                                                                                                   | **Fixed.** Now visible text.                                                                                                                                                                                                                                                                                |
| L8  | Low      | "Approve return" also submitted.                                                                                                                                                         | **Fixed.** The button reads "Approve and send return", and the slip says it will be sent.                                                                                                                                                                                                                   |
| L9  | Low      | The serial prompt said the orders differed even when both were returnable.                                                                                                               | **Fixed.**                                                                                                                                                                                                                                                                                                  |
| L10 | Low      | Demo reset runs without the per-case lock.                                                                                                                                               | **Not changed.** Reset is a demo control for a single local operator, and it deletes cases rather than updating them. Locking every case would add complexity without protecting a real flow. Recorded here and in the threat model's note on demo controls.                                                |
| L11 | Low      | The application layer hard-coded the retailer's policy ID.                                                                                                                               | **Fixed.** It is passed in from the dataset.                                                                                                                                                                                                                                                                |
